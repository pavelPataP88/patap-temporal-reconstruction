# PATAP v0.5 Anti-Tautology Audit

## Result: PASS, subject to the stated capture boundary

The public recorder observes Linux `open`/`openat` file-access syscalls from
actual third-party builds. `T(W)` publishes only opaque process identifiers,
SHA-256 fingerprints of files written by a process, and SHA-256 fingerprints
of files read by it. Paths, syscall positions, timestamps, source ordering,
build-system DAGs and producer process identifiers are omitted.

The evaluator is a separate code path. It reads the privileged syscall log and
defines a realized-use edge only when a process reads a concrete path whose
last earlier write in that execution belongs to another process. It is allowed
to use capture order solely for this evaluator-only artifact-instance decision;
that order is never serialized into public observations or supplied to E.

The public adapter does not join a reader to a writer. It serializes each
process's independently observed read and write fingerprints. The frozen E
performs its pre-existing generic fingerprint matching after the records are
shuffled. Thus the public representation is an observation byproduct, not an
encoding of evaluator edge pairs.

Known limit: a stable final fingerprint does not preserve every transient file
version. The evaluator retains the actual path-level use relation, while E may
return UNKNOWN or AMBIGUOUS. This is an expected information-loss limitation,
not a reason to inject evaluator truth into public data.
