# PATAP v0.5 External Validation Protocol

Source mechanism: v0.4 protocol/extractor freeze
`16619ec722cb4ccd88b4970bb946ff38e3405204`. The exact v0.4 matching rule is
embedded unchanged in `benchmarks/v05_external/run_external_validation.py`.

The frozen third-party corpus is `benchmarks/v05_external/projects.json`:

- `benhoyt/inih` at `577ae2dee1f0d9c2d11c7f10375c1715f3d6940c` — C/CMake;
- `BurntSushi/byteorder` at `5a82625fae462e8ba64cec8146b24a372b4d75c6` — Rust/Cargo;
- `mattn/go-isatty` at `c44dc0b9c702c76577fdb7898032969e0611efc2` — Go.

The external runner is Linux-only. Ubuntu uses `strace`, CMake, Rust Cargo and
Go supplied by the runner image. It clones exact commits, performs the frozen
commands, and captures file reads/writes. Public records are shuffled and use
opaque SHA-derived identifiers. The external evaluator is kept separate from
the public adapter as documented in the anti-tautology audit.

Controls: normal; all inputs removed; shuffled records; opaque ID replacement;
25% and 50% input-trace loss; and one false-trusted input trace in the same
public format. Random seed: 505001.

Pass gate: all three projects complete; aggregate direct precision >= 0.95 and
recall >= 0.80; each project precision >= 0.90 and recall >= 0.70; shuffle and
opaque-ID results are invariant; and input removal collapses recovery. Failure
means only that this frozen mechanism did not generalize under this protocol.
